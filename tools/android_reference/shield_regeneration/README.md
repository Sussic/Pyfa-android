## Finite reviewed process schedule

No EOS execution until the independent reviewer approves these exact exporter
files and the parent releases the serial lane. Three original-only processes,
in this order, each under external `timeout 180s` and address-space limit 1 GiB:

1. `defenses`: all 14 existing C01.3.1 defense fixture specs, unaltered equipment,
   settings, skill level and damage components. The 12 offered axis/effectivity
   combinations plus time starts 25/100 alongside 0 give 20 requests per fit.
   Includes all four single-type patterns, uniform and 3/7/11/19 asymmetric
   damage, hardener ACTIVE/ONLINE/OFFLINE, shield extender and other defenses.
2. `boundaries`: existing empty and Large Shield Extender Vexors; 20 requests each
   for equal/reversed/time-underflow/time-adjacent/large-finite ranges, null/150%
   starting shield, equal/reversed/clamped/underflow/adjacent shield inputs.
   Signed source-API negative time, negative starting shield, crossing/below-zero
   percentage clamps, and finite huge percentage/start overflow-then-clamp are
   included too. Negative time must yield above-capacity shield and negative rate.
   Normalized and actually limited ranges are retained separately for each fit;
   intermediate infinity is explicitly tagged, while accepted output stays finite.
3. `history`: existing active hardener, extender, and unchanged empty anchor.
   Four requests per fit at 27 stages. Original local module commands and genuine
   command undo/redo; shared character and original Shield Management / Shield
   Operation setLevel 5→4→5 with restoration; asymmetric, EM-only and all-zero
   fit-local original DamagePattern replacement/restoration. The latter skill and
   damage restoration wrappers do not claim desktop GUI undo implementation.
   The three pattern_zero stages are explicit source-only characterization: the
   current candidate rejects zero-total fit-local patterns, so those stages are
   not production mutation acceptance requirements. The other24 history stages
   are comparable through supported durable APIs.

Every observed fit is recalculated by the original service immediately before
reading, and every stage is repeated in reverse fit order. Reads must preserve
raw inputs. Actual fitting/publication/resources/slots and finite shield inputs
are checked before accepted evidence. The exact original source-column methods
return raw capacity HP and recharge seconds regardless of graph effectivity.

One separate no-EOS/no-DB source-AST test process covers all offered modes and
26 test methods: parser behavior, per-fit clamps, 0/25/100/null starting values,
reversed/equal/subnormal/duplicate coordinate ranges; signed source-API inputs;

clamping; zero capacity and zero recharge mode-specific validity; original

tiny effective divisor/nonfinite results, and huge positive time with a finite

capacity/recharge/resonance cases are helper behavior, not reachable legal fits.
JSON encodes synthetic nonfinite values explicitly rather than accepting them as
successful finite plotting output. Original x-mark methods remain out of scope.

## Exact source and safety boundary

The exporter executes whole unchanged original `FitGraph`, `FitShieldRegenGraph`,
Input/XDef/YDef, SmoothPointGetter and all four getter AST bodies. Fresh graphs
execute `getPlotPoints` → `_calcPlotPoints`, including normalize → limit → getter
→ Y then X denormalization and base fallback. No independent curve formulas,
sampling/clamping approximations, sorting or deduplication are substituted.
Instrumented wrappers only count calls/capture raw sampled arrays. Definitions,
getters, source columns and desktop parser/control wiring are source-hash bound.

Resolution is source-defined 200 intervals, zero refinement: normally 201 points,
equal/underflow singleton, or base zero-capacity percentage fallback 2 points.
Undefined arithmetic is retained as such in helper evidence, never fabricated 0.
Requested and effective inputs are distinct, including reversed endpoints.

Before fit construction, fail-fast wrappers block Fit cap/tank getters, simulation,
drain generation, CapSimulator reset/run and both cycle iterators. This proves
only this reference path. Production inherited preparation/admission resets are
independently qualified and are not falsely described as absent. No graph cycle
or capacitor model is required by the source.

The bootstrap uses the existing game DB through exact SQLite URI `mode=ro`, with
saved fits in memory. Verify its physical SHA before and after (68fb9ea9...) and
99,897,344-byte size; independently validate the environment's logical identity
(5857af3e...). These distinct identities are inherited from protected G05.1
DATASET-VERIFY.json and must never be conflated. No database copies, downloads, network, candidate
calculation imports, builds or device operations. Receipts bind imported/extracted
source, harnesses, fixture file, settings, effective inputs, resource limits,
per-stage LOCAL work, point counts, elapsed/RSS and blocked-call/network logs.
Outputs are exclusive new paths and failures retain partial evidence. The source
path is supplied by candidate-root `test-env.sh`. No environment changes are made.

## Desktop input semantics

`CtrlPanel` constructs FloatRangeBox for main range and FloatBox for starting
shield. Their OnText regex allows unsigned decimal tokens, with a single range
separator. `-5` is an incomplete `(None,5)` range, not negative five; `-5-0` is
rejected. FloatBox rejects typed negative/scientific forms; blank/dot becomes
None and original starting shield defaults to zero. Reversed positive endpoints
are allowed and sorted by the sampler. Shield values above 100 are allowed then
clamped per fit. Time has no source upper limiter. Signed time/ranges are valid
at the original Python API level and tested separately; they are not claimed as
desktop typed input support. Native signed inputs, if retained, must identify that
source-API extension honestly. No 2500-second remote-repair limiter is borrowed.
